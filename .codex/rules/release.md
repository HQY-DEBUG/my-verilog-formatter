# 发布与安装包保留规则

## 发布方式

- 插件身份固定为 `hanxuyao.hanxuyao-plugin`，当前发布目标为 `win32-x64`。
- 每次修改完成并通过验证后，自动执行完整打包发布流程；代码、资源、配置、文档和仓库规则修改均适用。用户已持续授权本仓库的必要本地提交、推送 `main`、创建并推送新版本标签以及 Marketplace 发布，无需逐次确认。
- 用户明确要求不发布或暂缓发布时遵从该次要求；只读任务和没有文件变更的任务不发布。检查失败时停止后续发布步骤并报告原因。
- 使用 `.github/workflows/publish.yml` 自动发布：分支推送执行编译、测试和打包，推送匹配版本的 `v<version>` 标签触发 Marketplace 发布。
- 使用 GitHub `marketplace` 环境中配置的 Microsoft Entra ID 联合身份认证；不得把密码、令牌或客户端密码写入仓库。
- 已完成联合登录与 Marketplace 发布权限验证。后续沿用现有配置；身份或权限变化时，先运行手动身份验证，再执行正式发布。

## 正式发布流程

1. 按上述默认发布授权和 `versioning.md` 同步版本清单、README 和 CHANGELOG；确认代码包含最新已完成的功能。
2. 安装锁定依赖和所需 MATLAB 构建依赖，先执行 `npm run compile`，再执行 `npm test -- --runInBand`。验证失败时停止发布。
3. 确认当前发布内容已提交，保留无关的未提交修改；推送目标提交到 `main` 后，确认该提交的云端构建成功。
4. 读取 `package.json` 的版本，在已验证的目标提交上创建 `v<version>` 标签并推送。不得把标签指向旧代码，也不得移动已用于发布的标签。
5. 等待对应标签的 GitHub Actions 发布任务完成，确认版本在 Marketplace 可用后再报告发布成功。只有登录、权限验证或打包成功时，不得声称已发布。
6. 发布失败时检查具体失败步骤；重试前确认 Marketplace 是否已接收该版本，避免盲目重复上传。

完成修改后不得默认停在本地提交或打包阶段，应持续执行到发布结果核验；已声明的用户例外或真实阻碍除外。具体操作见 `docs/自动发布.md`。

## 本地安装包保留

- 本地只保留一个最新验证通过的本插件 `.vsix` 安装包，统一放在仓库根目录，命名为 `hanxuyao-plugin-<version>-win32-x64.vsix`。
- 先生成或下载最新安装包，检查其内部发布者、插件名称、版本、目标平台及必要运行资源，再清理旧包；新包生成或检查失败时保留原包。
- 以安装包内部版本判断新旧，不仅凭文件名或修改时间；清理旧版本、同版本的临时包及重复包。
- 清理范围仅限本仓库根目录及明确属于当前任务的临时工作树中本插件的安装包。执行前列明文件并校验绝对路径，不递归清理其他目录，不删除其他插件或已安装的扩展。
- 清理后检查剩余安装包数量和保留文件路径，并在交付时说明保留版本。
