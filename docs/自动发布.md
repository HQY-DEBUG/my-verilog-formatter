# 插件自动发布

## 发布流程

推送分支会自动测试并生成 Windows x64 安装包；推送与 `package.json` 版本一致的 `v*` 标签后，会发布本次构建的同一个安装包。手动运行默认只构建；勾选验证身份也不会发布。

工作流使用 Microsoft Entra ID 与 GitHub OIDC，不保存长期发布令牌。身份尚未配置时，分支构建仍可运行，标签发布会明确报错。

## 一次性配置

### 1. 创建 Microsoft 发布身份

1. 登录 [Microsoft Entra 管理中心](https://entra.microsoft.com/)，确认账号可进入一个组织租户，并有注册应用的权限。若没有租户，先完成 Microsoft 官方的租户开通流程；本工作流不会代为开通收费服务。
2. 在“应用注册”中新建单租户应用 `hanxuyao-marketplace-publisher`，无需重定向 URI。
3. 记录“应用程序（客户端）ID”和“目录（租户）ID”。不要创建客户端密码。
4. 打开该应用的“证书和密码 → 联合凭据”，添加 GitHub Actions 凭据：

| 字段 | 值 |
| --- | --- |
| GitHub 组织/所有者 | `HQY-DEBUG` |
| 仓库 | `my-verilog-formatter` |
| 实体类型 | `Environment` |
| 环境名称 | `marketplace` |
| 颁发者 | `https://token.actions.githubusercontent.com` |
| 使用者 | `repo:HQY-DEBUG/my-verilog-formatter:environment:marketplace` |
| 受众 | `api://AzureADTokenExchange` |

### 2. 配置 GitHub 环境

在仓库 `Settings → Environments` 中新建 `marketplace`，添加两个 Environment secrets：

| 名称 | 内容 |
| --- | --- |
| `AZURE_CLIENT_ID` | 应用程序（客户端）ID |
| `AZURE_TENANT_ID` | 目录（租户）ID |

在该环境的部署分支和标签设置中，限制为 `main` 分支和 `v*` 标签。`main` 用于一次性的手动身份验证，标签用于正式发布。不需要授予 GitHub 仓库写入权限或 Azure 订阅资源角色。

### 3. 授权 Marketplace 发布者

1. 将工作流合入默认分支后，在 GitHub `Actions → 插件测试与发布 → Run workflow` 选择 `main` 并勾选“仅验证发布身份”。
2. 成功后，从运行摘要读取 Marketplace 成员 ID；它与应用的客户端 ID、对象 ID 不同。
3. 打开 [hanxuyao 发布者管理页面](https://marketplace.visualstudio.com/manage/publishers/hanxuyao)，在 `Members` 中添加该成员 ID，并授予 `Contributor`。
4. 若身份查询或添加成员失败，按页面错误检查 Azure DevOps 身份注册及租户关联；不要用客户端 ID 替代查询得到的成员 ID。身份验证成功只证明可以登录，最终发布权限仍需通过实际发布验证。

登录、创建租户以及授权步骤需要账号所有者完成；不要将密码、访问令牌或客户端密码写进仓库。

## 每次更新

先提交功能修改，同步 `package.json`、`package-lock.json`、README 和 `CHANGELOG.md` 的版本说明。确认准备发布后，将更新日志中的当前版本“未发布”替换为实际日期，再在对应提交上创建标签。

在 PowerShell 中执行：

```powershell
$releaseVersion = (Get-Content package.json -Raw | ConvertFrom-Json).version
git push origin main
git tag "v$releaseVersion"
git push origin "v$releaseVersion"
```

检查每条命令成功后再执行下一条。标签必须指向包含全部发布内容的已提交代码；本地未提交文件不会进入 GitHub 构建。发布成功后可在 Marketplace 查看结果；发布失败时查看 Actions 日志。已发布的同一平台版本不能重复上传，后续修复需要新版本。

## 当前构建约定

- 使用 Node.js 22 和固定版本的 `@vscode/vsce`。
- 使用 `npm ci` 安装锁定依赖，执行 `npm test -- --runInBand`。
- 若项目定义了 `setup:matlab`，先安装 MATLAB 集成所需依赖。
- `vsce package` 调用现有 `vscode:prepublish` 完成编译。
- 当前仓库没有顶层 LICENSE，打包延续 `--skip-license`，不会替项目选择许可证。
- `.github/`、`.codex/` 和开发文档不进入 VSIX。
